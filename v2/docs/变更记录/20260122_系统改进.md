## 二、文件存储架构重构

### 2.1 架构设计

#### 设计原则
1. **文件与素材分离**：独立的文件表实现真正的文件复用
2. **MD5去重**：相同文件只存储一份，节省存储空间
3. **OpenRTB兼容**：竞价时返回URL而非二进制数据

#### 架构图

```
┌─────────────────┐         ┌─────────────────┐
│  rtb_file       │         │ rtb_material    │
│  ───────────    │         │  ───────────    │
│  id (PK)        │    ┌────│  id (PK)        │
│  file_id (UK)   │────┤    │  material_id    │
│  file_md5 (UK)  │    │    │  creative_id    │
│  file_data      │    │    │  file_id (FK)   │
│  file_name      │    │    │  width          │
│  file_size      │    │    │  height         │
│  file_type      │    │    │  format         │
│  ...            │    │    │  ...            │
└─────────────────┘    │    └─────────────────┘
                       │
       同一文件可被     │
       多个素材引用     │
                       └───────────┐
                                    │
                          多个素材可引用
                          同一个文件
```

### 2.2 数据库表结构

#### rtb_file 表

```sql
CREATE TABLE `rtb_file` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `file_id` VARCHAR(128) NOT NULL COMMENT '文件唯一ID',
  `file_name` VARCHAR(255) NOT NULL COMMENT '原始文件名',
  `file_data` LONGBLOB NOT NULL COMMENT '文件二进制数据',
  `file_size` BIGINT NOT NULL COMMENT '文件大小(字节)',
  `file_md5` VARCHAR(32) NOT NULL COMMENT '文件MD5值',
  `file_type` VARCHAR(64) COMMENT '文件MIME类型',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_file_id` (`file_id`),
  UNIQUE KEY `uk_file_md5` (`file_md5`) COMMENT 'MD5唯一索引，用于去重',
  INDEX `idx_file_name` (`file_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文件表-存储上传的文件内容';

ALTER TABLE rtb_material
MODIFY COLUMN `file_id` VARCHAR(128) NOT NULL COMMENT '关联文件ID,rtb_file.file_id';
```

**关键设计点**：
- `file_md5` 唯一索引：实现文件去重
- `file_data` LONGBLOB：支持大文件存储（最大16MB，可扩展）
- `file_id` 业务ID：对外暴露，不暴露自增主键

### 2.3 核心实现

#### 文件上传服务

**位置**：`RtbFileServiceImpl.java:28-74`

**核心逻辑**：
```java
@Override
@Transactional
public String upload(MultipartFile file) {
    // 1. 读取文件内容
    byte[] fileData = file.getBytes();

    // 2. 计算MD5
    String fileMd5 = calculateMD5(fileData);

    // 3. 检查文件是否已存在
    RtbFileDO existingFile = fileMapper.selectOne(
        new LambdaQueryWrapper<RtbFileDO>()
            .eq(RtbFileDO::getFileMd5, fileMd5)
    );

    if (existingFile != null) {
        // 文件已存在，直接返回已有fileId
        log.info("文件已存在，复用文件: fileId={}", existingFile.getFileId());
        return existingFile.getFileId();
    }

    // 4. 创建新文件记录
    String fileId = "FILE_" + IdUtil.getSnowflakeNextId();
    RtbFileDO fileRecord = new RtbFileDO();
    fileRecord.setFileId(fileId);
    fileRecord.setFileData(fileData);
    fileRecord.setFileMd5(fileMd5);
    // ... 设置其他字段

    fileMapper.insert(fileRecord);
    return fileId;
}
```

**文件复用场景**：
1. 同一用户多次上传相同文件 → 返回相同fileId
2. 不同用户上传相同文件 → 返回相同fileId
3. 同一创意下重复上传文件 → 创建新的素材记录，但fileId相同
4. 不同创意使用相同文件 → 各创建独立素材记录，但fileId相同

### 2.4 HTTP文件访问

#### 文件下载接口

**位置**：`FileController.java:29-62`

**功能**：根据fileId返回文件内容，支持HTTP缓存

**核心特性**：
```java
@GetMapping("/{fileId}")
public ResponseEntity<byte[]> getFile(@PathVariable String fileId) {
    RtbFileDO fileRecord = fileMapper.selectOne(...);

    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.parseMediaType(fileRecord.getFileType()));
    headers.setContentDispositionFormData("inline", fileRecord.getFileName());

    // HTTP缓存控制
    headers.setCacheControl("public, max-age=3600");  // 公共缓存1小时
    headers.setETag("\"" + fileRecord.getFileMd5() + "\"");  // MD5作为ETag
    headers.setLastModified(DateTimeFormatter.RFC_1123_DATE_TIME
        .format(fileRecord.getCreateTime()));

    return new ResponseEntity<>(fileRecord.getFileData(), headers, HttpStatus.OK);
}
```

**缓存策略**：
- **Cache-Control**: `public, max-age=3600`
  - 允许CDN和浏览器缓存
  - 缓存时间1小时（适合静态素材）
- **ETag**: 使用MD5值
  - 文件内容变化时MD5必变
  - 支持条件请求 `If-None-Match`
- **Last-Modified**: 文件创建时间
  - 支持条件请求 `If-Modified-Since`

#### 文件信息接口

**位置**：`FileController.java:64-81`

**功能**：获取文件元信息（不含二进制内容）

**使用场景**：
- 竞价前检查文件大小

```java
@GetMapping("/{fileId}/info")
public ResponseEntity<RtbFileDO> getFileInfo(@PathVariable String fileId) {
```

### 2.5 OpenRTB竞价场景支持

#### 竞价响应中的文件引用

**设计原则**：
- OpenRTB bid响应返回**URL**，不返回二进制数据
- DSP通过URL异步获取素材文件
- 利用HTTP缓存减少服务器负载

**示例**：
```json
{
  "id": "bid-request-123",
  "seatbid": [{
    "bid": [{
      "id": "bid-1",
      "impid": "imp-1",
      "adm": "<img src=\"https://ad-domain.com/api/file/FILE_123456\" />",
      "nurl": "https://ad-domain.com/api/notify/win?bid_id=bid-1"
    }]
  }]
}
```

**优势**：
1. **响应速度快**：Bid响应不包含大文件，满足OpenRTB 100ms超时要求
2. **带宽节省**：相同文件通过CDN缓存，减少重复传输
3. **异步加载**：DSP浏览器并行请求多个素材文件

## 三、时间格式兼容性改进

### 3.1 问题背景

**错误现象**：
```
JSON parse error: Cannot deserialize value of type `java.time.LocalDateTime`
from String "2026-01-20 00:02:00": Text '2026-01-20 00:02:00' could not be parsed at index 10
```

**根本原因**：
- Spring Boot默认使用ISO 8601格式 (`yyyy-MM-dd'T'HH:mm:ss`)
- 前端Element Plus日期选择器使用空格分隔 (`yyyy-MM-dd HH:mm:ss`)

### 3.2 解决方案

#### Jackson多格式解析器

**位置**：`JacksonConfig.java`

**支持格式**：
```java
private static final List<String> DATE_TIME_FORMATS = Arrays.asList(
    "yyyy-MM-dd HH:mm:ss",      // 前端默认
    "yyyy-MM-dd'T'HH:mm:ss",     // ISO 8601
    "yyyy-MM-dd HH:mm:ss.SSS",   // 带毫秒
    "yyyy-MM-dd'T'HH:mm:ss.SSS"  // ISO带毫秒
);
```

**实现逻辑**：
```java
@Override
public LocalDateTime deserialize(JsonParser p, DeserializationContext ctxt) throws IOException {
    String dateTimeStr = p.getValueAsString();

    for (String format : DATE_TIME_FORMATS) {
        try {
            return LocalDateTime.parse(dateTimeStr,
                DateTimeFormatter.ofPattern(format));
        } catch (DateTimeParseException e) {
            // 尝试下一种格式
        }
    }

    throw new IOException("无法解析日期时间: " + dateTimeStr);
}
```

**自动配置**：
```java
@Configuration
public class JacksonConfig {
    @Bean
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        // ... 配置LocalDateTime反序列化器
        return mapper;
    }
}
```

### 3.3 影响范围

**适用字段**：
- `rtb_creative.start_time` - 创意开始时间
- `rtb_creative.end_time` - 创意结束时间
- 所有 `LocalDateTime` 类型的DTO字段

**无需修改**：
- 前端代码（保持原样）
- 后端实体类（自动应用）
- DTO注解（已添加 `@JsonFormat` 作为备用）

## 八、注意事项

### 8.1 文件大小限制

**默认限制**：Spring Boot最大上传1MB

**如需调整**，在 `application.yml` 配置：
```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB
```

### 8.2 数据库字段大小

**LONGBLOB容量**：最大16MB

**如需支持更大文件**：
- 使用 `LONGTEXT` 存储文件路径（文件系统存储）
- 或使用对象存储服务（OSS/S3）

### 8.3 MD5碰撞

**极低概率**：不同文件MD5相同

**应对方案**（如需要）：
- 添加文件大小作为第二判断条件
- 或使用SHA-256替代MD5

### 8.4 缓存失效

**文件更新场景**：
- 当前设计：文件不可变（MD5唯一）
- 如需更新：上传新文件，获取新fileId
- 素材更新：修改material记录的file_id
