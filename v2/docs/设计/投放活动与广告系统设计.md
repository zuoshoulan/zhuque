# 投放活动与广告系统设计文档

## 1. 概述

本系统采用**两层架构**设计投放活动和广告，符合OpenRTB DSP系统的业界实践。

### 1.1 架构层级

```
Campaign (投放活动)
  ↓ 1:N
Ad (广告)
  ↓ N:1
Creative (创意)
  ↓ 1:N
Material (素材)
```

### 1.2 两层架构说明

- **Campaign（投放活动）**: 管理预算、时间、状态等总体控制
- **Ad（广告）**: 完整的竞价单元，包含出价、定向、创意关联
- **Creative（创意）**: 创意内容，包含落地页、展示URL等
- **Material（素材）**: 具体的媒体文件（图片、视频等）

### 1.3 为什么选择两层？

1. **符合DSP系统特点**: OpenRTB实时竞价场景下，Ad是完整的竞价单元
2. **查询效率高**: 竞价时直接匹配Campaign→Ad，减少层级
3. **业界实践**: Beeswax、RTB4FREE等开源DSP均采用两层架构
4. **灵活性强**: 一个Campaign可包含多个Ad，每个Ad独立配置

## 2. 数据库设计

### 2.1 rtb_campaign（投放活动表）

```sql
CREATE TABLE `rtb_campaign` (
  -- 主键
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `campaign_id` VARCHAR(64) NOT NULL COMMENT '投放活动ID',

  -- 归属
  `advertiser_id` BIGINT NOT NULL COMMENT '广告主ID（sys_user.id）',

  -- 基础信息
  `name` VARCHAR(255) NOT NULL COMMENT '活动名称',
  `description` TEXT COMMENT '活动描述',

  -- 预算设置
  `budget` DECIMAL(15,2) NOT NULL DEFAULT 0 COMMENT '总预算（元）',
  `daily_budget` DECIMAL(15,2) DEFAULT NULL COMMENT '日预算（元），NULL表示不限制',
  `budget_used` DECIMAL(15,2) NOT NULL DEFAULT 0 COMMENT '已使用预算（元）',

  -- 时间设置
  `start_time` DATETIME NOT NULL COMMENT '开始时间',
  `end_time` DATETIME NOT NULL COMMENT '结束时间',
  `timezone` VARCHAR(32) DEFAULT 'Asia/Shanghai' COMMENT '时区',

  -- 状态
  `status` TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0=草稿/1=进行中/2=暂停/3=已完成/4=已取消',

  -- 投放设置
  `delivery_mode` TINYINT DEFAULT 1 COMMENT '投放方式：1=加速投放/2=均匀投放/3=手动投放',

  -- 审计字段
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `create_by` VARCHAR(50) DEFAULT NULL COMMENT '创建人',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '删除标记：0=未删除，1=已删除',

  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_campaign_id` (`campaign_id`),
  KEY `idx_advertiser_id` (`advertiser_id`),
  KEY `idx_status` (`status`),
  KEY `idx_start_time` (`start_time`),
  KEY `idx_end_time` (`end_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='广告投放活动表';
```

### 2.2 rtb_ad（广告表）

```sql
CREATE TABLE `rtb_ad` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `ad_id` VARCHAR(64) NOT NULL COMMENT '广告ID，对应OpenRTB的id',

  -- 归属
  `campaign_id` BIGINT NOT NULL COMMENT '投放活动ID',
  `advertiser_id` BIGINT NOT NULL COMMENT '广告主ID',
  `creative_id` BIGINT NOT NULL COMMENT '创意ID',

  -- 基础信息
  `name` VARCHAR(255) NOT NULL COMMENT '广告名称',

  -- 出价设置
  `bid_price` DECIMAL(10,2) NOT NULL COMMENT '出价（元/千次展示，CPM）',
  `bid_strategy` TINYINT DEFAULT 1 COMMENT '出价策略：1=固定CPM/2=智能出价',

  -- 状态
  `status` TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0=草稿/1=启用/2=暂停/3=已完成',

  -- 权重（用于同一活动下多个广告的分配）
  `weight` INT DEFAULT 100 COMMENT '权重，值越大分配越多流量',

  -- 审计字段
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `deleted` TINYINT NOT NULL DEFAULT 0,

  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ad_id` (`ad_id`),
  KEY `idx_campaign_id` (`campaign_id`),
  KEY `idx_creative_id` (`creative_id`),
  KEY `idx_advertiser_id` (`advertiser_id`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='广告表';
```

## 3. 表关系说明

### 3.1 关联关系

```
rtb_campaign (1) ──────── (N) rtb_ad
    ↓                            ↓
advertiser_id              advertiser_id
(sys_user.id)              (sys_user.id)

rtb_ad (N) ──────── (1) rtb_creative
    ↓
creative_id

rtb_creative (1) ──────── (N) rtb_material
    ↓
creative_id
```

### 3.2 数据权限

- 通过 `advertiser_id` (即 `sys_user.id`) 实现数据隔离
- 用户只能查看/操作自己创建的投放活动和广告
- 查询时强制过滤 `WHERE advertiser_id = currentUserId`

### 3.3 级联规则

- **删除Campaign**: 需要先删除或移走关联的Ad
- **删除Ad**: 直接删除，不影响Creative
- **删除Creative**: 需要先删除或移走关联的Ad和Material

## 4. 业务逻辑

### 4.1 状态流转

#### Campaign状态

```
草稿(0) ────────→ 进行中(1)
  ↓                 ↓
已取消(4)        暂停(2)
                   ↓
              已完成(3)
```

- **草稿→进行中**: 检查预算、时间、至少有1个Ad
- **进行中→暂停**: 允许暂停
- **暂停→进行中**: 允许恢复
- **任何状态→已取消**: 允许取消
- **进行中→已完成**: 时间到期或预算耗尽时自动完成

#### Ad状态

```
草稿(0) ────────→ 启用(1)
  ↓                 ↓
已删除          暂停(2)
                   ↓
              已完成(3)
```

### 4.2 预算控制

- Campaign级别检查总预算和日预算
- 竞价时检查Campaign剩余预算
- 预算耗尽时自动暂停Campaign下所有Ad

### 4.3 OpenRTB竞价映射

```
BidRequest
  └── Imp (广告位)
       ↓
查询匹配的Campaign (预算、时间、状态)
  ↓
查询匹配的Ad (出价、定向、创意)
  ↓
返回BidResponse
  ├── id: Ad.ad_id
  ├── adid: Ad.ad_id
  ├── crid: Creative.creative_id
  └── adm: Material文件内容
```

## 9. 附录：为什么不使用三层架构？

传统广告平台（Google Ads、Facebook Ads）使用三层：Campaign → Ad Group → Ad

但DSP系统使用两层的优势：
1. **实时性**: OpenRTB竞价要求毫秒级响应，层级越少越快
2. **简洁性**: Ad本身是完整竞价单元，不需要分组
3. **业界实践**: 主流DSP系统均为两层架构

如果未来需要更复杂的分组管理，可在不改变两层核心的前提下，通过Tag或Category标签实现软分组。
