# 后端项目部署指南

> **适用场景**: 生产环境部署、性能优化
> **最后更新**: 2025-01-29
> **JDK 版本**: JDK 21+ (推荐 JDK 21 LTS)

## 二、JVM 启动参数配置

### 核心原则

RTB 竞价服务对延迟有严格要求（60ms 内返回），JVM 配置需优先考虑：

1. ✅ **低延迟** - 使用 ZGC，停顿时间 < 1ms
2. ✅ **稳定性** - 避免运行时缺页中断
3. ✅ **高吞吐** - 分代 GC 提升吞吐量 15-20%

---

### 推荐配置（生产环境）

#### **RTB 竞价服务** (bid-java) - 低延迟优化

```bash
java -XX:+UseZGC \
     -XX:+ZGenerational \
     -XX:ZCollectionInterval=5 \
     -XX:+AlwaysPreTouch \
     -XX:+DisableExplicitGC \
     -Xms4g -Xmx4g \
     -jar bid-java-2.0.0.jar \
     --spring.profiles.active=prod
```

**参数说明**：

| 参数 | 作用 | 为什么重要 |
|------|------|-----------|
| `-XX:+UseZGC` | 启用 ZGC | 低停顿 GC，停顿 < 1ms |
| `-XX:+ZGenerational` | 分代 ZGC | 适合大量短生命周期对象，提升吞吐 15-20% |
| `-XX:ZCollectionInterval=5` | GC 间隔 5 秒 | 降低 GC 频率，减少与业务线程竞争 |
| `-XX:+AlwaysPreTouch` | 启动时预分配内存 | 避免运行时缺页中断导致延迟突增 |
| `-XX:+DisableExplicitGC` | 禁用 System.gc() | 避免第三方库触发意外 Full GC |
| `-Xms4g -Xmx4g` | 固定堆大小 4GB | 避免动态扩容的 STW |

**预期效果**：
- P99 延迟降低 15-20%
- Young GC 停顿 < 0.1ms
- Old GC 频率降低 10 倍

---

#### **管理后端** (zhuque-admin) - 通用配置

```bash
java -XX:+UseZGC \
     -XX:+ZGenerational \
     -XX:+AlwaysPreTouch \
     -Xms2g -Xmx2g \
     -jar zhuque-admin-2.0.0.jar \
     --spring.profiles.active=prod
```

**说明**：管理后端延迟要求不高，堆内存可以适当减小（2GB 足够）。

---

### 其他 GC 选项（备选）

#### **G1 GC** (JDK 11-17)

如果无法使用 JDK 21：

```bash
java -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=10 \
     -XX:G1ReservePercent=15 \
     -XX:InitiatingHeapOccupancyPercent=40 \
     -XX:+AlwaysPreTouch \
     -Xms4g -Xmx4g \
     -jar bid-java-2.0.0.jar
```

**对比**：
- G1 GC 停顿时间：~5-10ms
- ZGC 停顿时间：< 1ms
- **RTB 场景强烈推荐 ZGC**

## 三、启动脚本示例

### 开发环境

```bash
#!/bin/bash
# dev-start.sh

cd /path/to/zhuque-backend/bid-java

java -XX:+UseZGC \
     -XX:+ZGenerational \
     -Xms2g -Xmx2g \
     -jar target/bid-java-2.0.0.jar \
     --spring.profiles.active=dev
```

### 生产环境

```bash
#!/bin/bash
# prod-start.sh

APP_NAME="bid-java"
APP_HOME="/opt/zhuque"
APP_JAR="$APP_HOME/$APP_NAME-2.0.0.jar"
PID_FILE="$APP_HOME/$APP_NAME.pid"
LOG_DIR="$APP_HOME/logs"

# 创建日志目录
mkdir -p $LOG_DIR

# JVM 参数
JAVA_OPTS="-XX:+UseZGC \
-XX:+ZGenerational \
-XX:ZCollectionInterval=5 \
-XX:+AlwaysPreTouch \
-XX:+DisableExplicitGC \
-Xms4g -Xmx4g"

# 启动应用
nohup java $JAVA_OPTS \
-jar $APP_JAR \
--spring.profiles.active=prod \
>> $LOG_DIR/application.log 2>&1 &

echo $! > $PID_FILE
echo "✅ $APP_NAME started, PID: $(cat $PID_FILE)"
```

### 使用 systemd 管理（推荐）

创建 `/etc/systemd/system/zhuque-bid.service`：

```ini
[Unit]
Description=Zhuque RTB Bidding Service
After=network.target mysql.service redis.service

[Service]
Type=simple
User=zhuque
WorkingDirectory=/opt/zhuque
ExecStart=/usr/bin/java \
    -XX:+UseZGC \
    -XX:+ZGenerational \
    -XX:ZCollectionInterval=5 \
    -XX:+AlwaysPreTouch \
    -XX:+DisableExplicitGC \
    -Xms4g -Xmx4g \
    -jar /opt/zhuque/bid-java-2.0.0.jar \
    --spring.profiles.active=prod
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
SyslogIdentifier=zhuque-bid

[Install]
WantedBy=multi-user.target
```

管理命令：

```bash
# 重载配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start zhuque-bid

# 停止服务
sudo systemctl stop zhuque-bid

# 查看状态
sudo systemctl status zhuque-bid

# 查看日志
sudo journalctl -u zhuque-bid -f

# 开机自启
sudo systemctl enable zhuque-bid
```

## 四、堆内存大小建议

根据业务规模选择：

| 服务 | QPS | 堆内存 | 说明 |
|------|-----|--------|------|
| bid-java | < 500 | 2GB | 小规模测试 |
| bid-java | 500-2000 | 4GB | 中等规模（推荐）|
| bid-java | 2000-5000 | 8GB | 高并发场景 |
| zhuque-admin | - | 2GB | 管理后端 |
| zhuque-gateway | - | 1GB | API 网关 |

**监控建议**：
- 堆内存使用率应 < 70%
- 如果经常超过 85%，考虑扩容

## 五、GC 监控指标

### 关键指标

```bash
# 查看 GC 状态
jstat -gcutil <pid> 1000

# 输出示例：
#  S0     S1     E      O       M     CCS    YGC     YGCT     FGC    FGCT     GCT
#  0.00   0.00  10.00  25.00  95.00  90.00     30     0.100      1    0.050    0.150
```

**关注点**：
- **YGC**: Young GC 次数（分代 ZGC 会频繁）
- **YGCT**: Young GC 总时间（应该 < 0.1ms/次）
- **FGC**: Full GC 次数（应该很少，分代 ZGC 会显著降低）
- **GCT**: 总 GC 时间占比（应该 < 5%）

### GC 日志开启

```bash
java -XX:+UseZGC \
     -XX:+ZGenerational \
     -Xlog:gc*:file=/opt/zhuque/logs/gc.log:time,level,tags \
     -Xms4g -Xmx4g \
     -jar bid-java-2.0.0.jar
```

## 七、故障排查

### GC 导致延迟高

**症状**：P99 延迟突增，超过 60ms

**排查**：

```bash
# 1. 查看 GC 日志
tail -f /opt/zhuque/logs/gc.log | grep "pause"

# 2. 检查堆内存
jmap -heap <pid>

# 3. 导出堆转储
jmap -dump:format=b,file=/tmp/heap.hprof <pid>
```

**解决方案**：

1. **确认启用了 `-XX:+ZGenerational`**
   ```bash
   jinfo -flags <pid> | grep ZGenerational
   ```

2. **增加堆内存**（如果内存不足）
   ```bash
   -Xms8g -Xmx8g
   ```

3. **启用 `-XX:+AlwaysPreTouch`**（如果有缺页中断）

---

### 内存泄漏

**症状**：堆内存持续增长，GC 频率越来越高

**排查**：

```bash
# 1. 查看 GC 日志中的 Old 代使用率
# 如果 Old 代持续增长，可能是内存泄漏

# 2. 使用 MAT 分析堆转储
# 下载：https://www.eclipse.org/mat/
```

---

### 应用启动慢

**可能原因**：`-XX:+AlwaysPreTouch` 导致启动时预分配内存

**权衡**：
- 保留 `AlwaysPreTouch`：启动慢，但运行时延迟稳定 ✅ **推荐**
- 去掉 `AlwaysPreTouch`：启动快，但运行时可能有延迟突增

**建议**：生产环境保留，开发环境可去掉。

---

## 八、最佳实践总结

### ✅ 推荐做法

1. **生产环境必须使用 JDK 21+**
   - 分代 ZGC 对 RTB 场景提升显著

2. **固定堆大小** (`-Xms = -Xmx`)
   - 避免动态扩容的 STW

3. **启用 `-XX:+AlwaysPreTouch`**
   - 用启动时间换运行时稳定性

4. **禁用显式 GC**
   - 避免第三方库触发 Full GC

5. **使用 systemd 管理**
   - 自动重启、日志管理

### ❌ 避免做法

1. **不要使用 `-XX:MaxGCPauseMillis` 限制 ZGC**
   - 对 ZGC 几乎无效，反可能影响性能

2. **不要随意设置过大的堆**
   - 4GB 对大多数 RTB 场景足够
   - 过大堆可能导致单次 GC 变慢

3. **不要在生产环境使用 CMS 或 Parallel GC**
   - 停顿时间远高于 ZGC
